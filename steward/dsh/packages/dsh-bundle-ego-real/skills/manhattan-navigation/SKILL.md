# 曼哈顿路径导航

仅用于真机底盘。沿地图 X 方向到拐点，再沿 Y 方向到目标，使用现有工具，不编写或运行代码。这是途经点顺序，不是底层轨迹控制：NAVIS 会自行转向、规划和避障，不能承诺实际轨迹是严格直角折线。若任务要求严格轨迹或通道约束，说明当前工具不提供该保证，不冒充已满足。

## 输入与检查

从操作员或本轮 task context 取得最终目标 `x`、`y`（地图米制坐标）、`heading_deg`（相对地图 +X 的角度，−180 至 180）。缺少目标坐标或最终朝向时询问，不猜测物料位置。地图名可来自操作员、task context 或本次有效设备反馈；若指定地图与设备地图不同，停止，不切换地图。

使用操作员给定的合法超时和容差；未指定时，每段导航 `timeout_s=120`、`position_tolerance_m=0.05`、`heading_tolerance_deg=5`，状态查询 `timeout_s=5`。导航超时按段计算，不是整条路径的总期限；底盘限速由工具固定，skill 不覆盖。

先调用 `ego_state` 检查故障、运动权限和活动动作，再调用 `get_navigation_state` 获取起点。运动任务要求没有软件故障、运动已启用、没有活动动作；设备查询必须 `state=succeeded`、`pose_valid=true`，两层地图一致且非空，`scheduler_status` 与 `navigation_status.status` 均为 0、2 或 3。其他状态或缺失反馈均停止，不把缓存 ego_state 当作当前位姿。仅要求规划或解释时允许只读查询，不调用运动工具。

## X 后 Y 的执行顺序

记本次查询的起点为 `(cx, cy)`，最终目标为 `(tx, ty, th)`，所有导航都使用已核对的同一地图。

每次 `navigate_to_pose` 都必须完整填写七个参数：`x`、`y`、`heading_deg`、`map_name`、`timeout_s`、`position_tolerance_m`、`heading_tolerance_deg`。第二段也要重新填写超时和两个容差，工具不会继承上一段参数。

1. 若 `cx != tx` 且 `cy != ty`，设置拐点 `(tx, cy)`。当 `ty > cy` 时拐点 `heading_deg=90`；当 `ty < cy` 时为 `-90`。该朝向指向下一段 Y 方向，不是第一段 X 方向。先调用一次 `navigate_to_pose` 到拐点，传入全部目标、地图、每段超时和容差参数。
2. 只有拐点返回 `state=succeeded` 才进入下一段。若失败、被取消、超时、定位丢失或结果未知，终止此 skill，不发送最终目标、不自动重试、不清除故障。需要取消活动任务时使用 `body_stop` 并报告其反馈，不能将取消请求等同于物理停稳。
3. 调用一次 `navigate_to_pose` 到 `(tx, ty, th)`。若起点任一轴已与目标完全相同，跳过拐点，直接执行这一步。即使起点两轴都与目标相同，也保留最终位姿调用以处理最终朝向；不要因为位置重合就宣称完成。
4. 最终调用也必须 `state=succeeded` 才报告整条路径成功。报告实际执行的途经点、终点反馈位姿、位置及朝向误差；失败时说明失败在哪一段和哪些后续段未执行。设备反馈不是独立的物理停稳证明。

两段必须串行，不能并发下发或提前排队。第二段目标始终是操作员给定的最终位姿；不根据第一段误差挪动最终目标。这里只分解路径，不包含安全区后退、固定中心点、物料坐标、不可达目标收缩、升降或抓取；这些动作和现场数据不能凭空补入。
